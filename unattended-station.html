Unattended Station Host on Raspberry Pi

RayWn2StationHost is a separate Linux service for a station or repeater that should keep monitoring when nobody is logged in. It owns the WN-2 USB connection, shares live readings with paired RayWn2App clients, and records CSV history on the Pi even when no clients are connected.

Prepare the station

  1. Install the Station Host executable and its systemd service using the package or deployment instructions supplied to you. The commands below use the example service raywn2-station@pi and configuration /etc/raywn2/pi.json. Substitute the names used by your installation.
  2. Set up Pi USB access for the service account. In the station configuration, enter the exact WN-2 serial identity and choose VCP or D2XX. The Pi 5 test on Debian 13 verified a physical meter on both transports and boot startup on VCP. If your installation uses raywn2-vcp.service to register the WN-2, order the station unit after it. A temporary D2XX driver switch may revert when the device is reconnected or the Pi reboots.
  3. Set the listen address and port on your trusted LAN or VPN. Provide the station’s TLS certificate, matching private key, and a dedicated state directory. Use mode 0700 for that directory and mode 0600 for the configuration and private key, owned by the service account. Keep the certificate and pairing store when restarting or moving the service.
  4. Review the service’s device profiles, calibration and protection settings. They are stored separately from desktop settings. With RF off, disconnect the WN-2 from the desktop app before starting the service. Each USB open or recovery sends the existing all-outputs-OFF command and restores a compatible previously applied protection profile when one is stored for that station.

Example station configuration

Replace WN2_SERIAL with the serial shown in RayWn2App. The example listens on the Pi itself. For a separate client on your LAN or VPN, use the Pi’s address on that network, or use an SSH tunnel to the loopback listener.

{
  "stateDirectory": "/var/lib/raywn2-station-pi",
  "certificate": "/etc/raywn2/station-cert.pem",
  "privateKey": "/etc/raywn2/station-key.pem",
  "address": "127.0.0.1",
  "port": 47827,
  "historyIntervalSeconds": 5,
  "historySegments": 16,
  "devices": [
    {"identity": "WN2_SERIAL", "transport": "VCP"}
  ]
}

Start, stop and check the service

Run these commands in a terminal on the Pi using an account with administrator access.

sudo systemctl start raywn2-station@pi
systemctl status raywn2-station@pi
sudo journalctl -u raywn2-station@pi -n 50
sudo systemctl stop raywn2-station@pi

After a successful manual test, enable starts the service on future boots. Stop releases the meter for the current session but leaves boot startup enabled. Disable --now stops the service and turns off boot startup. Stop the service before connecting the same WN-2 from the desktop app.

sudo systemctl enable raywn2-station@pi
sudo systemctl disable --now raywn2-station@pi

Pair and monitor

Run the station commands as the service account. Use your WN-2’s exact serial in place of WN2_SERIAL. The status command shows the listener, certificate fingerprint, and device state. An invitation expires in two minutes and can be used once.

RayWn2StationHost --config /etc/raywn2/pi.json --status
RayWn2StationHost --config /etc/raywn2/pi.json --invite WN2_SERIAL

On the client, open Tools → Remote Station → Remote Client. Enter the Pi’s WSS address and port, the verified SHA-256 fingerprint, and the invitation code. In Instrument Properties, choose the remote identity ending in your WN-2 serial and confirm the RF channel. A running client can reconnect after a Pi reboot using its existing pairing. Opening a new desktop client session requires a fresh invitation.

To close access for all paired clients, run the command below. Each client will need a new invitation.

RayWn2StationHost --config /etc/raywn2/pi.json --revoke-all

History and recovery

After pairing, open Tools → Remote Station → Remote Client → Browse station history. Choose the device, a recording segment by its UTC start time, and a channel or All channels. Use Previous page and Next page to browse. Export selected segment saves all matching rows in that segment to a CSV on the client computer. Live readings continue while you browse or export.

Choose Refresh recordings to include recent samples and files. Each browse or export has a fixed end within the selected segment. If the host rotates the segment out during an export or loses its connection, the incomplete export is discarded. The button is available when the paired host supports browsing.

Open the history folder inside the station’s configured state directory. Each interval records one row per RF channel, with timestamps, identity, link and relay status, RF, DC and auxiliary values. Blank measurement cells indicate unavailable data. The host limits the number of 2 MiB CSV segments according to its retention setting. Copy files you want to keep before they rotate out.

If the WN-2 disappears, the host keeps retrying the configured identity and transport. The paired client shows unavailable readings until fresh telemetry returns. If recording stops, check the service journal for storage errors and confirm the state directory is writable. The recorder retries after 30 seconds. An unknown relay status indicates the host did not receive a recognized relay status value.

For direct access by monitoring software, see the optional read-only HTTPS / JSON API.
