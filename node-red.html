What Node-RED does

Node-RED runs on a station computer and can display readings received through your MQTT broker. A flow is a saved arrangement of steps that receives, processes and displays messages. The sample flows are optional; local RayWn2App operation does not depend on them. Have Node-RED and the broker configured before importing the supplied RayWn2App examples. Preserve existing flows and enter your own broker/security settings. Do not expose an unprotected station dashboard to the Internet.

Import and set up examples

In the Windows installation, choose Help → Node-RED Examples to open the folder containing the JSON files. With the default installation path, it is C:\Program Files\RayWn2App\Node-RED. In a source checkout, the same files are in examples/node-red. Use the Node-RED editor on your station computer. Enter its configured address and port, using HTTPS if the server is configured for it.

  • raywn2-telemetry.json is the native example. Start here for the station dashboard, trends, events and warnings.
  • wavenode-compatibility.json translates one selected WN-2 stream to Dave’s WaveNode-to-MQTT format.
  • wavenode-sample-dashboard.json is the optional dashboard for the translated stream. Import it with the compatibility flow.
  1. In Node-RED, use Menu → Import and select the JSON file. Import it to a new flow tab. Check existing flows for matching routes, such as /station or /wavenode-sample, before deploying. If a route is already in use, leave the duplicate undeployed and update the existing flow only when you intend to replace it.
  2. Open an MQTT node on the imported tab and edit its broker settings. Enter the broker host, port and credentials. The sample’s localhost setting means the computer running Node-RED. For TLS, use the hostname on the broker certificate and configure its trusted CA as needed. The native dashboard account needs read access to the RayWn2App topics. The optional adapter also needs write access to its compatibility topics.
  3. In RayWn2App, open Tools → MQTT Telemetry and start publishing to that broker. The examples expect the default raywn2 topic root. If you use a custom root, adjust the imported subscriptions and their topic parsing to match.
  4. For compatibility, set the publisher ID and exact WN-2 identity in Select source → Dave topics. In the sample dashboard, set sourceLabel in Bounded values and freshness to identify that WN-2. Its MQTT subscription and Function node must use the same output topic root as the adapter. Keep only one publisher of the legacy wavenode/# topics.
  5. The examples use built-in Node-RED nodes, so no Dashboard add-on is needed. Review the imported tab, then click Deploy. Check that the MQTT input shows connected. Open /station on the Node-RED server, or /wavenode-sample for the compatibility dashboard. Compare the device identity, timestamps and readings with RayWn2App.

Station dashboard

Open the configured Node-RED address followed by /station in your browser. Each device card identifies its source, physical/simulated state, readings and freshness. Check the identity before comparing it with the main application. UNAVAILABLE / STALE means the card has no current valid data. It is not zero RF. Clear unavailable devices hides those cards while keeping live devices. Repeated unavailable messages should not immediately recreate a cleared card; it returns when usable live data returns.

Station-health warnings

The dashboard can display the published station-health information and its configured warning rules. Review the device, condition and timestamp. Acknowledging a dashboard warning does not reset the WN-2 relay or correct the station condition. Rules and display state are separate from RayWn2App's native email and SWR protection settings. Keep the distinction clear when configuring alerts.

Trends and event history

From /station, open Measurement trends and station events, or /station/history. Select the publisher/device stream and channel. The view plots recent RF/DC readings and shows observed station events. Missing data breaks traces instead of drawing a false zero. The history is bounded and is not a permanent station log. Export selected history as JSON or measurements as CSV before restarting or redeploying the flow. Clear selected history affects that stream's history, not live device control.

Compatibility sample

The optional compatibility adapter translates a selected source to the message format expected by WaveNode-to-MQTT consumers. Dave's original dashboard is a separate third-party example. The RayWn2App-compatible sample adds clear unavailable/stale indications; its page is /wavenode-sample. Choose the intended publisher, WN-2 and channel mapping. Do not merge multiple devices into one unidentified legacy stream. Preserve the native /station dashboard when adding a compatibility example.

Troubleshooting

First check that RayWn2App reports publishing active. Then check broker connection/security and the flow's selected source. A working browser page does not prove new MQTT messages are arriving. Confirm timestamps and status before using a reading. These dashboards monitor data; the supplied flows do not provide WN-2 hardware control.
