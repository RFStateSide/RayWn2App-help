Host certificates — Create, remember and renew

Prepare the certificate on the host before you invite clients. A certificate lets the client verify the station's identity and encrypt its connection. The accompanying private key stays on the host. Each client operator verifies the certificate's SHA-256 fingerprint with you.

Create the files once

Use an installed OpenSSL command-line tool on the host, or obtain a PEM certificate and matching unencrypted private key from your certificate administrator. Create a dedicated private folder in your user profile, outside shared folders and source repositories, and open a terminal in it.

Windows — PowerShell and the full OpenSSL path

Open PowerShell on the Station Host computer. The following example uses OpenSSL installed at C:\Program Files\OpenSSL-Win64\bin\openssl.exe. If you installed it elsewhere, substitute its actual location. You can use the full path even when typing openssl by itself reports that the command was not found.

First create the private station folder if needed, then make it the current folder:

New-Item -ItemType Directory -Force -Path "$env:LOCALAPPDATA\RFStateside\RayWn2App\remote-station" | Out-Null
Set-Location "$env:LOCALAPPDATA\RFStateside\RayWn2App\remote-station"

$env:LOCALAPPDATA automatically selects your Windows account's local application-data folder. For example, on Ray's computer the location is C:\Users\ray\AppData\Local\RFStateside\RayWn2App\remote-station. The folder you select determines where the two new files are saved; it does not need to contain OpenSSL itself.

If these files already belong to a working host, keep them and follow Renew or use another certificate instead of overwriting them. Regenerating the certificate changes the host identity and requires clients to pair again.

For the first certificate, run this next line as one command. Keep the leading & and the quotes around the executable path:

& 'C:\Program Files\OpenSSL-Win64\bin\openssl.exe' req -x509 -newkey rsa:3072 -nodes -days 365 -subj "/CN=RayWn2App-Station" -keyout station-key.pem -out station-cert.pem

The & tells PowerShell to run the program at the quoted path. Quotes keep the spaces in Program Files together. This full-path form does not require changing your Windows PATH setting. After it finishes, the station folder contains station-key.pem and station-cert.pem.

Linux and macOS — Terminal

Open Terminal in your dedicated private station folder. With OpenSSL available, run this as one command:

openssl req -x509 -newkey rsa:3072 -nodes -days 365 -subj "/CN=RayWn2App-Station" -keyout station-key.pem -out station-cert.pem

This creates a new 3072-bit RSA key and a self-signed certificate valid for 365 days. Keep station-key.pem private. The key is unencrypted so the station can start unattended. Restrict the folder and key to the host account and administrators. In a dedicated Linux or macOS TLS folder, run chmod 700 . and chmod 600 station-key.pem. On Windows, check the folder's Properties → Security permissions.

Select and remember

Open Tools → Remote Station → Station Host, use each Browse… button to open the station folder and choose station-cert.pem as the TLS certificate and station-key.pem as the TLS private key, then Start host. After a successful start, RayWn2App remembers those paths, the listen address and port. Keep the files at those locations. The dialog shows expiry in UTC and warns within 30 days of expiration.

To display the fingerprint and validity dates, stay in the station folder. On Windows PowerShell, use the same full executable path:

& 'C:\Program Files\OpenSSL-Win64\bin\openssl.exe' x509 -in station-cert.pem -noout -fingerprint -sha256 -dates

On Linux or macOS Terminal:

openssl x509 -in station-cert.pem -noout -fingerprint -sha256 -dates

Renew or use another certificate

Generate replacement files before the old certificate expires. Use different filenames, such as station-key-new.pem and station-cert-new.pem, so the existing identity remains available while you prepare the replacement. With the desktop host stopped, select the replacement files and start it to save the new paths.

A new certificate has a new fingerprint. Verify it with each client operator, pair clients again and update instrument bindings to the new remote host identity. Stopping a desktop host revokes its running pairings. The Pi service reads certificate paths from its station JSON. Update those paths and restart that service when replacing its identity.

If the certificate expired, a file is missing, or the file is invalid, review the message beside the certificate settings and choose valid files. Check the computer clock if the certificate appears not yet valid. Continue with desktop host setup or Pi service setup.
