Unattended Station Host on Windows and Raspberry Pi

RayWn2StationHost runs as a native Windows service or a separate Linux service for a station or repeater that should keep monitoring when nobody is logged in. It owns the WN-2 USB connection, shares live readings with paired RayWn2App clients, and records CSV history on the Pi even when no clients are connected.

Windows Station Host service

A dedicated Station Host can monitor the meter without a desktop login. Its settings are separate from your normal RayWn2App settings. Install the WaveNode Windows USB drivers first. VCP may need the additional USB Serial driver step. With RF off, disconnect the meter in the desktop app before starting the service. Both cannot use the same meter at once.

Cannot connect from the desktop app? Check the service

One program owns each physical WN-2 USB connection. A running Station Host service can keep the meter open even when its desktop window is closed. Installing or opening RayWn2App does not stop an existing service. This applies to both D2XX and VCP.

  1. Open the Windows Start menu, search for Services, and open it. Look for your RayWn2 Station Host service. Its installed name may differ; the Alpha review setup used RayWn2StationReview, while the normal default is RayWn2StationHost.
  2. If you want direct USB access in the desktop app, select the matching service and choose Stop. Approve administrator access if requested. Wait until its status is no longer Running, then use Discover → select the meter → Connect in RayWn2App.
  3. If the service should keep monitoring, leave it running and connect the desktop app as a Remote Client instead of opening the local USB device.

Stopping the service disconnects its remote viewers and pauses its recording and MQTT publishing. Saved settings, pairings and recorded history are retained. RayWn2App does not currently stop a Windows service from its own controls.

Alternatively, open PowerShell as administrator. Check these common names, then stop only the service that owns your meter. Substitute your installation's name when different:

Get-Service -Name RayWn2StationHost,RayWn2StationReview `
  -ErrorAction SilentlyContinue
Stop-Service -Name RayWn2StationReview
Get-Service -Name RayWn2StationReview

Stop does not change startup type. If an automatically started service should remain off after reboot, open its Properties in Windows Services and set Startup type → Manual. To resume unattended monitoring, first Disconnect the meter in the desktop app, then Start the service in Windows Services. Remote viewers can reconnect when it is ready.

  1. Use the supplied Station Host runtime and reviewed station configuration. Supply your exact WN-2 serial, VCP or D2XX, TLS certificate and key, and listen address. The TLS setup instructions explain certificate generation. Keep the same certificate and state across restarts.
  2. Run the supplied station-service.ps1 installation script in PowerShell as administrator. It installs a dedicated passwordless service account, protects configuration and key files, and leaves the service stopped with Manual startup. It does not change firewall rules.
  3. Review calibration and protection for the service's own device profiles. A fresh service uses nominal profiles. USB open/recovery sends the established all-outputs-OFF initialization and restores a compatible previously applied protection profile when one is provisioned.
  4. Start the service, check its status, create a one-time pairing code locally, then pair your Remote Client using the verified fingerprint. Readings and recorded history remain read-only.

These examples use the default name RayWn2StationHost. Run the script from the folder supplied for your installation. Substitute the runtime and source configuration paths:

.\station-service.ps1 -Action Install `
  -RuntimeDirectory C:\StationPreparation\runtime `
  -Config C:\StationPreparation\station.json
.\station-service.ps1 -Action Start
.\station-service.ps1 -Action Status
.\station-service.ps1 -Action Stop

To enable boot startup, use -AutoStart when installing, or select Automatic (Delayed Start) in Windows Services after a successful manual test. Intentional Stop stays stopped. The service retries an unavailable configured meter. Test startup on the intended station before unattended use.

Use elevated PowerShell for local administration. Replace WN2_SERIAL with the actual serial:

$folder = 'RayWn2StationHost\RayWn2StationHost'
$hostExe = Join-Path $env:ProgramFiles "$folder\RayWn2StationHost.exe"
$stationConfig = Join-Path $env:ProgramData "$folder\station.json"
& $hostExe --config $stationConfig --status
& $hostExe --config $stationConfig --invite WN2_SERIAL
& $hostExe --config $stationConfig --revoke-all

The code expires after two minutes. Keep pairing codes and API tokens private. For an optional enabled HTTPS API, use --api-token WN2_SERIAL and --api-revoke-all. For a custom service name, use -ServiceName NAME with the script and --service-name NAME with the executable.

Recorded CSV segments are in the service's private state\history folder under ProgramData. Browse/export them from the Remote Client. The private state\station-host.log and Windows Services help diagnose startup and connection failures. A Running service may be waiting for a meter: check status as well. Remove stops and unregisters the service while preserving its settings, TLS identity and history:

.\station-service.ps1 -Action Remove

Windows service setup is independent of the desktop Station Host. This service provides WSS, optional HTTPS and recorded history. It does not run desktop email or audio. Optional service MQTT publishing has its own configuration; see unattended MQTT.

Raspberry Pi Station Host service

Prepare the station

  1. Install the Station Host executable and its systemd service using the package or deployment instructions supplied to you. The commands below use the example service raywn2-station@pi and configuration /etc/raywn2/pi.json. Substitute the names used by your installation.
  2. Set up Pi USB access for the service account. In the station configuration, enter the exact WN-2 serial identity and choose VCP or D2XX. The Pi 5 test on Debian 13 verified a physical meter on both transports and boot startup on VCP. If your installation uses raywn2-vcp.service to register the WN-2, order the station unit after it. A temporary D2XX driver switch may revert when the device is reconnected or the Pi reboots.
  3. Set the listen address and port on your trusted LAN or VPN. Provide the station’s TLS certificate, matching private key, and a dedicated state directory. Use mode 0700 for that directory and mode 0600 for the configuration and private key, owned by the service account. Keep the certificate and pairing store when restarting or moving the service.
  4. Review the service’s device profiles, calibration and protection settings. They are stored separately from desktop settings. With RF off, disconnect the WN-2 from the desktop app before starting the service. Each USB open or recovery sends the existing all-outputs-OFF command and restores a compatible previously applied protection profile when one is stored for that station.

Example station configuration

Replace WN2_SERIAL with the serial shown in RayWn2App. The example listens on the Pi itself. For a separate client on your LAN or VPN, use the Pi’s address on that network, or use an SSH tunnel to the loopback listener.

{
  "stateDirectory": "/var/lib/raywn2-station-pi",
  "certificate": "/etc/raywn2/station-cert.pem",
  "privateKey": "/etc/raywn2/station-key.pem",
  "address": "127.0.0.1",
  "port": 47827,
  "historyIntervalSeconds": 5,
  "historySegments": 16,
  "devices": [
    {"identity": "WN2_SERIAL", "transport": "VCP"}
  ]
}

Start, stop and check the service

Run these commands in a terminal on the Pi using an account with administrator access.

sudo systemctl start raywn2-station@pi
systemctl status raywn2-station@pi
sudo journalctl -u raywn2-station@pi -n 50
sudo systemctl stop raywn2-station@pi

After a successful manual test, enable starts the service on future boots. Stop releases the meter for the current session but leaves boot startup enabled. Disable --now stops the service and turns off boot startup. Stop the service before connecting the same WN-2 from the desktop app.

sudo systemctl enable raywn2-station@pi
sudo systemctl disable --now raywn2-station@pi

Pair and monitor

Run the station commands as the service account. Use your WN-2’s exact serial in place of WN2_SERIAL. The status command shows the listener, certificate fingerprint, and device state. An invitation expires in two minutes and can be used once.

RayWn2StationHost --config /etc/raywn2/pi.json --status
RayWn2StationHost --config /etc/raywn2/pi.json --invite WN2_SERIAL

On the client, open Tools → Remote Station → Remote Client. Enter the Pi’s WSS address and port, the verified SHA-256 fingerprint, and the invitation code. In Instrument Properties, choose the remote identity ending in your WN-2 serial and confirm the RF channel. A running client can reconnect after a Pi reboot using its existing pairing. A restarted client can reuse a saved profile when Remember pairing was selected and the host retains its grant; otherwise create a fresh invitation.

To close access for all paired clients, run the command below. Each client will need a new invitation.

RayWn2StationHost --config /etc/raywn2/pi.json --revoke-all

History and recovery

After pairing, open Tools → Remote Station → Remote Client → Browse station history. Choose the device, a recording segment by its UTC start time, and a channel or All channels. Use Previous page and Next page to browse. Export selected segment saves all matching rows in that segment to a CSV on the client computer. Live readings continue while you browse or export.

Choose Refresh recordings to include recent samples and files. Each browse or export has a fixed end within the selected segment. If the host rotates the segment out during an export or loses its connection, the incomplete export is discarded. The button is available when the paired host supports browsing.

Open the history folder inside the station’s configured state directory. Each interval records one row per RF channel, with timestamps, identity, link and relay status, RF, DC and auxiliary values. Blank measurement cells indicate unavailable data. The host limits the number of 2 MiB CSV segments according to its retention setting. Copy files you want to keep before they rotate out.

If the WN-2 disappears, the host keeps retrying the configured identity and transport. The paired client shows unavailable readings until fresh telemetry returns. If recording stops, check the service journal for storage errors and confirm the state directory is writable. The recorder retries after 30 seconds. An unknown relay status indicates the host did not receive a recognized relay status value.

For direct access by monitoring software, see the optional read-only HTTPS / JSON API.

Service files in Alpha v0.0.2

The Windows installation contains a StationHost folder with the separate runtime, installation script, masked password helper and an example configuration. The desktop installer does not start a service. The Linux bundle includes a station-host launcher and install-station-service.sh. Run the latter from the installed bundle with your private configuration path to prepare an optional user service. It leaves the service stopped and disabled. An existing service is preserved. Review and test it before enabling boot startup.

Optional unattended MQTT publishing

A Station Host can publish without a desktop login. MQTT defaults OFF. Configure the broker, TLS, a unique publisher ID, topic base, username and interval in the private station configuration. Use a publish-only broker account. It publishes the same identified measurements and availability as the desktop app; see MQTT setup and Node-RED. A broker failure does not stop WSS, HTTPS or history recording.

Never enter passwords in the configuration file. On Windows, run the supplied set-mqtt-password.ps1 helper in administrator PowerShell with the installed host executable and configuration paths. It prompts without showing the password and uses Windows encryption in the protected service state directory. On Linux, run the command below as the service user. The credential is stored in an owner-only file inside the private state directory, separately from desktop saved passwords. Restart the service after provisioning. Keep TLS certificate verification enabled; service certificate trust can differ from desktop trust.

systemd-ask-password 'Station MQTT password:' |
  ./station-host \
    --config /absolute/private/station.json \
    --mqtt-password-stdin

Missing or mismatched credentials leave MQTT stopped with a diagnostic. The service continues acquiring and recording. Once configured, broker reconnect is automatic. Change mqtt.enabled to false and restart to disable publishing. The runtime guide supplied in the StationHost folder lists the configuration fields and service commands.
