Read measurements through the HTTPS API

The optional read-only API lets a monitoring program read your station directly without an MQTT broker. You can continue using normal Remote Clients at the same time. The API cannot operate outputs or reset protection.

Set up the host first

  1. Connect your WN-2 and follow Set up the desktop Station Host. Start the host with its certificate and private key.
  2. In Remote Station, select HTTPS / JSON API. Leave HTTPS port 47828, or choose a free port different from the Station Host port. Select Start HTTPS API.
  3. Select the WN-2 identities your monitoring software may see. Select Create read-only token, then Copy token. Store it privately in that software. You cannot display it again after closing this dialog.
  4. Configure your monitoring software to trust the host certificate and use a server name matching that certificate. Refer to Certificates. Allow the chosen HTTPS port only on your intended LAN or VPN.

The desktop API stays off at application startup. Its port and token grants are remembered. Stop HTTPS API preserves tokens. Revoke all API tokens removes their access while keeping WSS pairings. Stopping Station Host closes HTTPS too. Keep tokens out of shared files, URLs and screenshots.

For integrations, read the API v1 developer reference and working examples.

What monitoring software can read

Every request uses HTTPS and an Authorization: Bearer header containing its private token. The token only allows its selected devices. The version 1 endpoints are:

  • /api/v1/status — service status and history availability.
  • /api/v1/devices — selected device identities and connection states.
  • /api/v1/readings — current forward/reflected average and peak watts, SWR, auxiliary/DC readings, units and freshness. Add ?device=YOUR-SERIAL for one device.
  • /api/v1/history/segments?device=YOUR-SERIAL and /api/v1/history/page — retained history from an unattended host.

Readings use the same calibrated measurements as the host. A successful request can still report an unavailable device. Check fresh, sample time and measurement status. Unavailable or invalid values are null; a genuine zero remains zero. Monitoring software should clear old readings if requests stop succeeding.

Unattended Pi host

In your private service configuration, add "apiPort": 47828 before starting the service. Leaving it out, or setting it to zero, disables HTTPS. The same certificate and address are used for WSS and HTTPS. Create a token locally as the service account:

RayWn2StationHost --config /absolute/path/station.json --api-token YOUR-SERIAL
RayWn2StationHost --config /absolute/path/station.json --status
RayWn2StationHost --config /absolute/path/station.json --api-revoke-all

Repeat --api-token with another serial in the same command to grant several meters to one token. Copy the returned secret once. Only its hash and device selection are stored. Keep the service state directory private and retain it across restarts.

History and limits

History requests return named columns and rows with a continuation cursor. Preserve the returned end, pass next as offset, and continue until more is false. If a segment has rotated away, refresh the list. History uses the host's existing bounded CSV storage. It is not a promise of thirty days of recordings. Desktop hosts do not currently record this server-side history.

Eight concurrent HTTPS connections and two simultaneous history reads are supported. Poll at a moderate rate, such as once per second. API access is advisory monitoring. Hardware protection remains local to the WN-2.
